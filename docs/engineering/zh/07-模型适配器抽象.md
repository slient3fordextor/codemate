# 模型适配器抽象

## 目标

隔离具体模型 provider，让 API 和服务层不直接依赖 OpenAI、Anthropic、Ollama 或其他 SDK。

## 抽象接口

建议定义统一协议：

```python
class ModelAdapter:
    async def stream_chat(self, request):
        ...
```

返回统一 chunk：

```text
ModelChunk
  type
  content
  input_tokens
  output_tokens
  finish_reason
  raw
```

## 推荐目录

```text
app/adapters/models/
  __init__.py
  base.py
  openai_compatible.py
  local.py
  mock.py
```

## MVP provider

第一阶段建议实现：

- `mock`：用于本地开发和测试。
- `openai_compatible`：支持 OpenAI 兼容 API。

本地模型适配器可以先保留接口，不急于实现复杂能力。

## 重试与超时

模型适配器层应处理：

- 请求超时。
- 最多重试次数。
- provider 错误转换。
- token usage 归一化。

不要把 provider 原始异常直接抛给 API 层。

## 验收标准

- chat service 只依赖抽象接口。
- mock adapter 可以稳定跑通 SSE。
- OpenAI 兼容 adapter 的错误会转换为统一错误码。
- provider 配置不泄露到日志。

## 风险点

- 如果 API 层直接调用具体 SDK，后续多模型路由和本地模型支持会变得困难。
- 不统一 usage 统计会影响成本可视化和成功指标。
