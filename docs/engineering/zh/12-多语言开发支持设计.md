# 多语言开发支持设计

## 目标

为 CodeMate 建立可扩展的多编程语言支持能力，使对话、上下文收集、代码生成、测试命令建议和后续代码修改能力不被某一种语言绑定。

本文档关注后端工程设计，不直接实现完整 IDE 语义能力。

## 设计原则

1. **语言能力可插拔**：新增语言时优先新增 adapter，不修改对话主流程。
2. **先项目级，再语义级**：MVP 先识别文件、项目配置、依赖和测试命令，后续再接入 LSP 或 tree-sitter。
3. **能力分级暴露**：不同语言可以处于不同成熟度，不要求所有语言同时支持完整能力。
4. **上下文安全优先**：多语言上下文收集必须复用工作区安全边界，不能绕过文件访问适配器。
5. **模型提示统一生成**：语言相关 prompt 由语言 adapter 贡献，ChatService 不硬编码具体语言规则。

## 能力分级

| 等级 | 名称 | 能力 | 适用阶段 |
| --- | --- | --- | --- |
| L1 | 文本级支持 | 识别语言、读取当前文件、解释和生成代码块 | MVP 起步 |
| L2 | 项目级支持 | 识别项目配置、依赖管理、测试命令、相关文件 | MVP 主力 |
| L3 | 语义级支持 | 符号索引、定义跳转、引用查找、结构化重构建议 | 后续增强 |
| L4 | 自动修改级支持 | 生成 patch、运行测试、基于错误迭代修复 | Agent 阶段 |

第一阶段建议：

| 语言 | 初始等级 | 说明 |
| --- | --- | --- |
| Python | L2 | 当前后端本身使用 Python，优先支持 pyproject、pytest、ruff、mypy |
| JavaScript | L2 | 支持 package.json、npm/pnpm/yarn、常见测试脚本 |
| TypeScript | L2 | 在 JavaScript 基础上增加 tsconfig 识别 |
| Go | L1 | 先识别 go.mod 和基础文件结构 |
| Rust | L1 | 先识别 Cargo.toml 和基础文件结构 |
| Java | L1 | 先识别 Maven / Gradle 项目 |

## 推荐目录结构

```text
app/services/language/
  __init__.py
  interfaces.py
  detector.py
  registry.py
  context.py
  factory.py
  models.py
  adapters/
    __init__.py
    python.py
    javascript.py
    typescript.py
    go.py
    rust.py
```

职责划分：

| 文件 | 职责 |
| --- | --- |
| `interfaces.py` | 集中保留 LanguageInfo、ProjectInfo、CodeContext、LanguageAdapter 等对外接口 |
| `detector.py` | 根据路径、扩展名、配置文件识别语言和项目类型 |
| `registry.py` | 管理语言 adapter 注册和查找 |
| `context.py` | 统一把语言检测和 adapter 输出转换为对话上下文 |
| `factory.py` | 创建默认语言上下文服务和检测规则 |
| `adapters/*` | 每种语言自己的规则 |

## 核心数据结构

```python
from dataclasses import dataclass
from pathlib import Path


@dataclass(frozen=True)
class LanguageInfo:
    language: str
    file_path: Path | None
    project_type: str | None
    package_manager: str | None
    confidence: float


@dataclass(frozen=True)
class ProjectInfo:
    root: Path
    language: str
    config_files: list[Path]
    source_roots: list[Path]
    test_roots: list[Path]
    package_manager: str | None


@dataclass(frozen=True)
class CodeContext:
    language: str
    current_file: Path | None
    selected_text: str | None
    related_files: list[Path]
    project_summary: str
    system_hints: list[str]
```

## Adapter 协议

```python
from typing import Protocol
from pathlib import Path


class LanguageAdapter(Protocol):
    language: str
    supported_extensions: set[str]

    def detect_project(self, workspace_root: Path, file_path: Path | None) -> ProjectInfo | None:
        ...

    def collect_context(
        self,
        project: ProjectInfo,
        current_file: Path | None,
        selected_text: str | None,
    ) -> CodeContext:
        ...

    def build_system_hints(self, project: ProjectInfo) -> list[str]:
        ...

    def get_test_command(self, project: ProjectInfo) -> list[str] | None:
        ...

    def get_format_command(self, project: ProjectInfo) -> list[str] | None:
        ...
```

上层服务只依赖 `LanguageAdapter`，不直接判断 Python、TypeScript、Go 等具体语言。

## 语言识别策略

语言识别采用多信号组合：

| 信号 | 示例 | 权重 |
| --- | --- | --- |
| 文件扩展名 | `.py`、`.ts`、`.go` | 高 |
| 项目配置文件 | `pyproject.toml`、`package.json`、`go.mod` | 高 |
| lock 文件 | `uv.lock`、`pnpm-lock.yaml`、`Cargo.lock` | 中 |
| shebang | `#!/usr/bin/env python` | 中 |
| 目录约定 | `src/`、`tests/`、`cmd/` | 低 |

当信号冲突时，以当前文件语言优先，项目类型作为补充。例如在 Python 项目中编辑 `README.md`，当前文件语言是 Markdown，但项目类型仍然是 Python。

## 上下文收集策略

上下文分为三层：

| 层级 | 内容 | 生命周期 |
| --- | --- | --- |
| 当前上下文 | 当前文件、选中代码、用户输入 | 单次请求 |
| 语言上下文 | 项目配置、依赖、测试工具、格式化工具 | 当前请求动态生成 |
| 项目上下文 | 文件树摘要、相关文件片段、索引摘要 | 后续可缓存 |

MVP 不做复杂语义索引，先按语言规则收集少量高价值文件：

| 语言 | 优先上下文文件 |
| --- | --- |
| Python | `pyproject.toml`、`requirements.txt`、当前模块附近的 `__init__.py`、`tests/` 中同名测试 |
| JavaScript | `package.json`、`jsconfig.json`、当前文件附近模块 |
| TypeScript | `package.json`、`tsconfig.json`、当前文件附近模块、类型定义文件 |
| Go | `go.mod`、当前 package 内 `.go` 文件、同目录 `_test.go` |
| Rust | `Cargo.toml`、当前 crate 的 `src/lib.rs` 或 `src/main.rs` |

所有文件读取必须通过工作区文件访问适配器，继承大小限制、路径校验、敏感信息检测和默认忽略规则。

## 对话服务集成

当前 `ChatService` 已支持 `current_file` 和 `selected_text`。后续可调整为：

```text
ChatRequest
  message/messages
  session_id
  current_file
  selected_text

ChatService
  1. 从 current_file 检测 LanguageInfo
  2. 从 registry 获取 adapter
  3. adapter 收集 CodeContext
  4. 把 CodeContext 转成 system/context message
  5. 调用 ModelAdapter
```

目标是让 ChatService 的主流程稳定：

```python
language_info = language_detector.detect(request.current_file)
adapter = language_registry.get(language_info.language)
code_context = adapter.collect_context(project, current_file, selected_text)
messages = prompt_builder.build(request, code_context, session_memory)
```

## Prompt 生成规则

语言 adapter 只贡献结构化提示，不直接拼接完整大段 prompt。

示例：

```text
Current language: Python
Project type: FastAPI backend
Package manager: uv
Testing preference: pytest
Formatting preference: ruff
Use existing project style and avoid introducing new frameworks unless necessary.
```

PromptBuilder 负责统一格式化，避免不同 adapter 输出风格不一致。

## 测试和命令识别

MVP 只生成建议命令，不自动执行。

| 语言 | 测试命令识别 |
| --- | --- |
| Python | 优先 `pytest`，其次 `python -m pytest` |
| JavaScript | 从 `package.json scripts.test` 读取 |
| TypeScript | 同 JavaScript，额外识别 `tsc --noEmit` |
| Go | `go test ./...` |
| Rust | `cargo test` |

自动执行测试属于后续 Agent 能力，应进入任务系统并受权限控制。

## 配置建议

可以在 `Settings` 中增加语言相关配置：

```text
LANGUAGE_SUPPORT_ENABLED=true
LANGUAGE_DEFAULT_LEVEL=L1
LANGUAGE_CONTEXT_MAX_FILES=8
LANGUAGE_CONTEXT_MAX_BYTES=120000
LANGUAGE_ENABLE_TREE_SITTER=false
LANGUAGE_ENABLE_LSP=false
```

配置必须保守，避免一次请求把大量源码发送给模型。

## 里程碑

### M1：语言识别和 adapter 框架

- 新增 `LanguageInfo`、`ProjectInfo`、`LanguageAdapter`。
- 实现 `LanguageDetector`。
- 注册 Python、JavaScript、TypeScript 最小 adapter。
- 单元测试覆盖扩展名和配置文件识别。

### M2：项目级上下文

- Python 识别 `pyproject.toml`、pytest、ruff。
- JS/TS 识别 `package.json`、`tsconfig.json`、测试脚本。
- ChatService 使用语言上下文生成 system message。
- 增加上下文大小限制测试。

### M3：扩展语言

- 增加 Go、Rust、Java L1 adapter。
- 文件树摘要中标记语言和项目类型。
- 前端代码块展示复用语言识别结果。

### M4：语义级能力预留

- 评估 tree-sitter 用于符号切分。
- 评估 LSP 用于定义、引用和诊断。
- 语义索引进入独立服务，不塞进 ChatService。

## 验收标准

- 新增语言不需要修改 ChatService 主流程。
- Python、JavaScript、TypeScript 可以识别项目配置和测试命令。
- 当前文件和选中文本仍然只作为单次请求上下文，不写入 L1 会话记忆。
- 所有上下文文件读取都经过工作区安全边界。
- 对未知语言有稳定降级行为：按纯文本代码处理。

## 风险点

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 上下文过大 | 多语言项目可能文件多、依赖复杂 | 限制文件数量和总字节数 |
| 敏感信息泄露 | 配置文件可能包含 token 或密钥 | 复用敏感信息检测和默认忽略规则 |
| adapter 规则膨胀 | 每种语言规则越来越多 | 保持 adapter 小而清晰，复杂能力拆到独立服务 |
| 语义能力过早复杂化 | LSP 进程管理、索引缓存成本高 | MVP 先做 L1/L2 |
| 命令执行风险 | 测试/格式化命令可能产生副作用 | 第一阶段只建议，不自动执行 |
