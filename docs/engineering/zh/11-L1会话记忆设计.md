# L1/L2/L3 分层记忆设计

> 文档定位：设计版。说明记忆模块的架构、信任边界和取舍。
> 当前请求如何运行见
> [`docs/流程/03-后端对话编排与会话记忆.md`](../../流程/03-后端对话编排与会话记忆.md)。

## 目标与范围

记忆模块解决四件事：同一会话连续追问、进程重启恢复、单机多进程共享，以及按全局/项目作用域学习长期偏好。

| 层级 | 内容 | 默认边界 |
| --- | --- | --- |
| L1 | 最近 `user/assistant` 原文 | 每会话 10 轮，按整体 Token 预算再次裁剪 |
| L2 | 超出 L1 的结构化摘要块 | 1536 Token，保留来源范围和压缩元数据 |
| L3 | 用户明确表达的稳定偏好 | 最多注入 20 条，区分 global/project |

默认 SQLite 文件为 `~/.codemate/memory.sqlite3`。该设计只承诺单机多进程，不承诺多机一致性。

## 模块边界

- `SessionMemoryStore`：异步存储协议，以及能力、审计和遗忘接口。
- `InMemorySessionMemoryStore`：只实现进程内 L1，能力接口明确返回“不持久化、不跨进程”。
- `SQLiteSessionMemoryStore`：实现 L1/L2/L3、WAL、多进程恢复、迁移和管理操作。
- `TokenCounter`：OpenAI 兼容已知模型使用 `tiktoken`；其他模型使用显式标记的 UTF-8 保守估算。
- `ContextBudgetPlanner`：统一计算模型输入、输出预留和协议余量。
- `PreferenceExtractor`：提取稳定偏好，并把当前轮直接要求作为临时指令参与冲突检测。
- `ContextConflictDetector`：按 `scope/category/key/value` 做确定性裁决。
- `DeterministicMemoryCompressor`：执行无模型的规范化、结构化抽取和紧急裁剪。

`ChatService` 只依赖存储协议，不直接执行 SQLite 语句。

## Token 预算

整体预算使用下式，而不是只限制 L2：

```text
input_budget
  = model_context_window
  - requested_or_default_output_tokens
  - protocol_margin
```

默认输出预留 1024 Token，协议余量为模型窗口的 5%。当前 user 消息、文件/选区上下文和操作模式是必需上下文；它们本身超限时返回 `CONTEXT_BUDGET_EXCEEDED`。

剩余预算依次分配给完整的 L1 轮次、相关 L3 偏好和 L2 摘要块。L1 只按完整的 user/assistant 对加入，不产生孤立消息。每次流式请求先发送 `context.usage`，包含 `counter_id`、`estimated`、输入 Token、记忆 Token、输入预算和输出预留。

旧变量 `SESSION_MEMORY_MEDIUM_TERM_MAX_CHARS` 只触发弃用警告，不会被静默换算；新变量是 `SESSION_MEMORY_MEDIUM_TERM_MAX_TOKENS`。

## 信任与冲突裁决

历史摘要和长期偏好来源于旧用户文本或模型回答，不能提升成 `system` 指令。L2/L3 以 `role=user, name=memory_context` 的低信任历史数据注入，并明确声明当前请求和当前项目证据优先。

确定性优先级如下：

```text
当前轮 user 指令
  > 当前工作区 system 事实
  > 当前会话 L1 新状态
  > 项目 L3
  > 全局 L3
  > L2 历史摘要
```

同一 L3 key 出现新值时，旧记录改为 `active=0` 并写入 `memory_conflicts`，不立即物理删除。读取时，当前轮直接要求会排除冲突的 L3；L1 的更新指令会过滤 L2 中相反的摘要行；项目 L3 在当前项目内覆盖全局 L3。

当前已实现结构化确定性检测。没有可识别 key 的自由文本不会被伪装成精确冲突；可选语义判定和 `uncertain` 人工裁决尚未接入模型调用。

## 智能压缩

L2 使用多个 `SummaryChunk`，不再维护一个反复截断的字符串。每个块记录：

- 内容、Token 数、来源轮次起止 ID；
- 必保项，以及为后续跨层审计预留的冲突 ID 字段；
- 压缩阶段、原因、输入 Token、丢失项；
- 压缩版本和 `counter_id`。

已实现的默认路径：

1. C1 规范化空白并去掉重复项；
2. C2 抽取约束、决策、未完成事项、错误/路径/错误码证据，以及请求和结果；
3. 摘要块总量超限时，合并相邻旧块并重新计数；
4. 只有可恢复的低优先级行可进入 C4 裁剪，丢失项写入元数据。

压缩后会验证所有必保文本仍存在。验证失败会回滚本次记忆写入并产生 `memory.warning`，原始旧轮次不会因为一次失败的摘要而被删除。C3 模型语义压缩仍是可选后续能力，当前不会额外发起模型请求或产生费用。

当摘要自己再次超出上下文时，系统先合并最旧摘要块，再按 Token 重新执行 C2/C4；请求阶段仍装不下时，最旧 L2 块不注入。当前问题和必要 system 上下文不会因摘要超限而被删除。

## 持久化与迁移

SQLite schema 当前版本为 3：

| 表 | 用途 |
| --- | --- |
| `memory_sessions` | 会话元数据 |
| `memory_turns` | L1 原文和幂等 `request_id` |
| `memory_summary_chunks` | L2 分块摘要及压缩审计元数据 |
| `long_term_preferences` | L3 key/value、作用域、active/superseded 状态 |
| `memory_conflicts` | 偏好冲突关系、裁决和项目作用域 |

数据库按 `user_version` 顺序执行 v1 -> v2 -> v3 migration；新增列检查后再执行，支持中断后重试。程序拒绝打开高于自身支持版本的数据库。

所有公开存储操作是 async，阻塞的标准库 `sqlite3` 调用放到 `asyncio.to_thread()`。读取使用显式事务固定同一快照；写入使用 `BEGIN IMMEDIATE`、WAL 和 5000ms `busy_timeout`。`request_id` 唯一索引保证同一请求重试不会重复追加一轮。

## 隐私与遗忘

启用 `ENABLE_SENSITIVE_CONTENT_DETECTION` 时，私钥块、API key、访问 token、密码、Cookie、Authorization、常见云密钥和 JWT 在落盘前替换为 `[REDACTED]`；含敏感内容的句子不会成为 L3 偏好。该规则同时检查 user 和 assistant 文本。

管理接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/memory/capabilities` | 查看当前后端真实能力 |
| `GET /api/v1/memory/preferences` | 查看 active 和已 superseded 偏好 |
| `GET /api/v1/memory/conflicts` | 查看冲突与裁决审计 |
| `DELETE /api/v1/memory/preferences/{id}` | 删除单条偏好及关联冲突 |
| `DELETE /api/v1/memory/sessions/{id}` | 删除单个会话 |
| `DELETE /api/v1/memory/project` | 清理当前项目记忆，不碰全局偏好 |
| `DELETE /api/v1/memory/global-preferences` | 显式清理全局偏好 |

## 失败策略

- 读取记忆失败：开流前返回 SSE `error`，code 为 `MEMORY_STORE_ERROR`，不静默无记忆降级。
- 模型失败：返回 provider 的结构化 SSE `error`，不记录半截回答。
- 回答完成后记忆写入失败：保留已完成回答，并追加 `memory.warning`。
- 必需上下文超预算：返回 `CONTEXT_BUDGET_EXCEEDED`，不删除当前指令后继续调用模型。

## 已知边界

- C3 语义压缩和低置信度 `uncertain` 冲突裁决尚未实现。
- 当前文件事实依靠更高信任的 system 上下文覆盖历史；尚未把任意代码事实规范化为可审计 `MemoryItem`。
- SQLite 文件未加密；权限会收紧为目录 `0700`、文件 `0600`。
- 管理 API 当前依赖应用本身的部署边界；公开部署前仍需接入身份认证。
