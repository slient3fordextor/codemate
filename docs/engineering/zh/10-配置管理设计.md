# 配置管理设计

## 目标

配置管理用于统一 CodeMate 后端的运行参数、密钥入口、本地工作区边界和模型 provider 设置。

它要解决四个问题：

1. 业务代码不直接读取环境变量。
2. 本地运行、测试、后续部署使用同一套配置入口。
3. API Key、工作区路径等敏感配置有明确边界。
4. 后续新增模型 provider、存储和安全策略时不用重写配置体系。

## 配置入口

统一入口是：

```text
app/core/config.py
```

业务代码应通过 `get_settings()` 或依赖注入获取配置，不应直接调用 `os.getenv()`。

## 配置来源

配置读取顺序由 `pydantic-settings` 处理：

1. 环境变量。
2. 本地 `.env` 文件。
3. 代码默认值。

仓库提供 `.env.example` 作为示例，真实 `.env` 不提交。

## 配置分组

当前脚手架保留一个 `Settings` 入口，同时提供分组属性：

| 分组 | 用途 |
| --- | --- |
| `settings.app` | 应用名称、版本、环境、debug |
| `settings.workspace` | 本地工作区根路径、文件大小限制、目录规模限制 |
| `settings.storage` | 数据库地址、是否启用持久化 |
| `settings.model` | 模型 provider、base url、模型名、API Key、超时和重试 |
| `settings.security` | 敏感信息检测、限流开关和限流额度 |
| `settings.logging` | 日志级别、JSON 日志开关、访问日志开关 |

这样设计是为了兼容环境变量的平铺写法，同时让代码使用时有清晰语义。

## 环境变量

示例见根目录 `.env.example`。

核心配置：

```text
APP_NAME=CodeMate
APP_VERSION=0.1.0
ENVIRONMENT=local
DEBUG=false

WORKSPACE_ROOT=.
WORKSPACE_MAX_FILE_BYTES=1000000
WORKSPACE_MAX_TREE_ENTRIES=5000

STORAGE_ENABLED=false
DATABASE_URL=sqlite+aiosqlite:///./codemate.db

MODEL_PROVIDER=mock
MODEL_BASE_URL=
MODEL_NAME=mock-model
MODEL_API_KEY=
MODEL_TIMEOUT_SECONDS=60
MODEL_MAX_RETRIES=2
```

## 本地工作区配置

`WORKSPACE_ROOT` 是本地文件访问的安全边界。

配置加载后会执行：

```text
expanduser().resolve()
```

这样可以把 `.`、`~`、相对路径统一成绝对路径。后续 `FileSystemAdapter` 必须基于 `settings.workspace.root` 做路径校验，不能自行信任请求里的路径。

## 模型配置

MVP 默认：

```text
MODEL_PROVIDER=mock
```

这是为了让本地开发、测试和 CI 不依赖真实模型 API，也不产生费用。

支持的 provider：

```text
mock
openai_compatible
ollama
```

当 `MODEL_PROVIDER=openai_compatible` 时，必须配置 `MODEL_BASE_URL`。API Key 是否必须由具体 provider 策略决定，但不应在健康检查、日志或错误响应中输出明文 key。

## 密钥策略

MVP 阶段建议：

- API Key 优先从环境变量或 `.env` 读取。
- `.env` 不提交。
- 健康检查只返回 `configured` 或 `not_configured`。
- 日志不输出 `MODEL_API_KEY`。
- 后续 Web 配置 API Key 时，不直接明文存数据库。

## 日志配置

当前配置：

```text
LOG_LEVEL=INFO
LOG_JSON_ENABLED=false
ACCESS_LOG_ENABLED=true
```

`ACCESS_LOG_ENABLED=false` 时，请求访问日志不输出，但 request id 中间件仍然生效。

`LOG_JSON_ENABLED` 是为后续结构化日志预留，目前脚手架先使用标准 logging 格式。

## 测试策略

配置测试应覆盖：

- 默认值。
- 环境变量覆盖。
- `WORKSPACE_ROOT` 规范化。
- provider 约束。
- 配置缓存可清理。

测试中修改环境变量后，应调用：

```python
get_settings.cache_clear()
```

避免测试之间共享缓存配置。

## 验收标准

- 所有业务代码都从 `Settings` 获取配置。
- 根目录存在 `.env.example`。
- `.env` 已加入 `.gitignore`。
- 工作区根路径会被规范化。
- `mock` provider 可在无 API Key 情况下运行。
- `pytest` 覆盖配置默认值、环境变量覆盖和 provider 校验。
