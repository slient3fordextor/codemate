# 任务状态与存储设计

## 目标

为长任务、会话、消息、反馈和模型配置建立清晰的持久化边界。

## MVP 存储选择

建议 MVP 默认使用 SQLite。后续团队模式或远程部署再支持 PostgreSQL。

配置示例：

```text
DATABASE_URL=sqlite+aiosqlite:///./codemate.db
```

## 核心实体

```text
Session
Message
Task
Feedback
ModelConfig
ProjectIndex
```

## Task 状态

建议字段：

```text
id
type
status
progress
session_id
started_at
completed_at
error_code
error_message
metadata
```

状态枚举：

```text
pending
running
succeeded
failed
cancelled
```

## 数据边界

默认持久化：

- 会话元数据。
- 消息摘要和必要上下文引用。
- 任务状态。
- 用户反馈。
- 模型配置元数据。
- 项目索引摘要。

默认不持久化：

- 完整源码。
- 明文 API Key。
- 大段 prompt 原文。

## 迁移策略

建议引入 Alembic 管理数据库迁移。即使 MVP 数据模型简单，也应避免手写一次性建表逻辑扩散。

## 验收标准

- 任务状态可通过 API 查询。
- SSE 对话可以关联 task id。
- 模型调用失败时任务状态会更新为 failed。
- 用户可删除会话和项目索引。

## 风险点

- 没有任务状态会导致长请求不可追踪。
- 持久化完整源码会扩大隐私和安全风险。
- 没有迁移体系会让后续数据模型演进困难。
