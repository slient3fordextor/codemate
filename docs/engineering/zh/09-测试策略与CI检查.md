# 测试策略与 CI 检查

## 目标

建立最小测试矩阵和持续检查命令，保证 FastAPI 骨架后续演进时不破坏安全边界和核心接口。

## 测试分层

建议测试分为：

- API 测试。
- 服务层测试。
- 适配器测试。
- 安全边界测试。
- 配置和错误处理测试。

## MVP 必测项

优先覆盖：

- `/api/v1/health`。
- 配置加载。
- 统一错误响应。
- 路径穿越拦截。
- 符号链接逃逸拦截。
- `.env` 和私钥默认不可读。
- SSE mock 流式输出。
- 模型 adapter 错误转换。
- 任务状态流转。

```text
mypy
```

## CI 检查命令

本地与 CI 统一执行：

```bash
make check
make test-safety
```

`make check` 包含 Ruff、格式检查、`mypy app tests scripts`、pytest、Node 皮肤回归、文档文件目标链接检查、独立 venv 的 wheel 安装与真实 HTTP/CLI 烟测。无需真实模型；安装运行依赖需要缓存或网络。仓库截图不作为运行资源打包。

独立安全 job 在 Ubuntu 22.04 安装 Bubblewrap，执行 `make test-safety`；缺沙箱或隔离失败必须失败，不能用 skip 替代。新增覆盖包括任务各修改入口的跨进程竞争、桌面多 worker 竞争与崩溃释放，以及新目录交付的文本/二进制/空文件、符号链接拒绝和失败恢复。

## 测试数据

测试应使用临时目录作为工作区，不读取开发者真实项目路径。

敏感文件测试应构造临时文件，例如：

```text
.env
id_rsa
config-with-token.txt
```

## 验收标准

- 新增 PR 通过统一门禁；轮次/Token 的完整累计恢复仍对应 O-04，不以库级 checkpoint 测试代替 CLI 接通证据。
- 安全边界测试失败时不能合并。
- mock 模型能在无外部网络和无 API Key 情况下完成测试。

## 风险点

- 没有路径安全测试，本地文件访问很容易在重构中回退。
- 如果测试依赖真实模型 API，会导致 CI 不稳定且产生费用。
