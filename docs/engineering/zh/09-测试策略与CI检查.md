# 测试策略与 CI 检查

## 目标

建立最小测试矩阵和持续检查命令，保证 FastAPI 骨架后续演进时不破坏安全边界和核心接口。

## 测试分层

建议测试分为：

- API 测试。
- 服务层测试。
- 适配器测试。
- 安全边界测试。
- 配置和错误处理测试。

## MVP 必测项

优先覆盖：

- `/api/v1/health`。
- 配置加载。
- 统一错误响应。
- 路径穿越拦截。
- 符号链接逃逸拦截。
- `.env` 和私钥默认不可读。
- SSE mock 流式输出。
- 模型 adapter 错误转换。
- 任务状态流转。

## 推荐工具

```text
pytest
pytest-asyncio
httpx
ruff
mypy
```

## CI 检查命令

建议 CI 至少执行：

```bash
ruff check .
ruff format --check .
mypy app tests
pytest
```

## 测试数据

测试应使用临时目录作为工作区，不读取开发者真实项目路径。

敏感文件测试应构造临时文件，例如：

```text
.env
id_rsa
config-with-token.txt
```

## 验收标准

- 新增 PR 至少通过 lint、format、typecheck 和 pytest。
- 安全边界测试失败时不能合并。
- mock 模型能在无外部网络和无 API Key 情况下完成测试。

## 风险点

- 没有路径安全测试，本地文件访问很容易在重构中回退。
- 如果测试依赖真实模型 API，会导致 CI 不稳定且产生费用。
