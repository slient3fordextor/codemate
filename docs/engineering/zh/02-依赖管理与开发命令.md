# 依赖管理与开发命令

## 目标

统一项目依赖、开发命令、格式化、lint、测试和类型检查方式，降低本地部署和开源协作成本。

## 推荐依赖管理

建议使用 `pyproject.toml` 作为统一配置入口。

MVP 基础依赖：

```text
fastapi
uvicorn[standard]
pydantic-settings
httpx
```

测试与工程化依赖：

```text
pytest
pytest-asyncio
ruff
mypy
```

存储相关依赖可在实现存储步骤时加入：

```text
sqlalchemy
aiosqlite
alembic
```

## 推荐开发命令

建议提供统一命令：

```bash
make dev
make test
make lint
make format
make typecheck
```

如果暂时不引入 `Makefile`，也应在文档中固定等价命令：

```bash
uvicorn app.main:app --reload
pytest
ruff check .
ruff format .
mypy app tests
```

## 配置建议

`pyproject.toml` 应至少包含：

- Python 版本约束。
- 运行依赖。
- 开发依赖。
- Ruff 配置。
- Pytest 配置。
- Mypy 配置。

## 验收标准

- 新贡献者可以根据一个命令启动开发服务。
- 测试、lint、格式化和类型检查命令固定。
- 依赖不散落在多个未说明的文件中。

## 风险点

- 依赖无锁定会导致不同环境行为不一致。
- 没有统一命令会增加开源贡献和 CI 配置成本。
