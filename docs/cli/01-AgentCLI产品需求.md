# CodeMate Agent CLI 产品需求

## 1. 产品定位

CodeMate Agent CLI 是本地优先的交互式编码代理。它面向已打开终端、正在处理真实代码仓库的开发者：用户描述目标，代理先理解项目和约束，再在明确的权限范围内读取文件、编辑代码、执行命令和验证结果，并持续展示过程。

产品体验接近 Codex 的交互式编码代理，而不是把聊天回答复制到终端：一次任务是可追踪的“理解 -> 计划/执行 -> 验证 -> 交付”闭环。

### 1.1 核心原则

- 本地优先：项目文件、命令和任务状态默认留在用户机器；向模型发送内容前遵守工作区和敏感信息策略。
- 用户保持控制：有副作用的操作必须有可理解的预览、授权依据和可撤销边界。
- 事实优先：文件内容、Git 状态、测试输出等工具结果高于模型猜测和历史记忆。
- 渐进授权：读取、改文件、执行命令、联网和危险操作分别授权，不能由模型自行提升权限。
- 可恢复和可审计：每次编辑、命令、审批和失败都应能在本会话中追溯；文件变更以 diff 呈现。
- 终端原生：交互在 TTY 中高效完成，同时支持面向脚本的非交互调用。

### 1.2 目标用户与任务

| 用户 | 典型任务 | CLI 应交付的结果 |
| --- | --- | --- |
| 日常开发者 | 增加功能、修复缺陷、理解模块 | 已修改的文件、验证结果和简短变更摘要 |
| 初级工程师 | 解释报错、拆解任务、学习项目 | 有证据的解释、可执行计划或经确认的修改 |
| 维护者 | 重构、补测试、审查变更 | 小步 diff、测试结果、遗留风险 |
| DevOps 工程师 | 排查构建、脚本与 CI 问题 | 受控命令结果、建议或项目内修改 |

## 2. 使用模型

### 2.1 两种工作方式

交互模式是默认体验：

```text
codemate
> 修复登录接口的 500，并运行相关测试
```

用户可在同一会话继续追问、补充约束、批准待执行动作，或中断当前任务。CLI 必须展示当前工作区、会话状态、模型流式输出和每次工具调用的摘要。

单任务模式用于脚本与 CI：

```text
codemate run "检查当前改动并给出风险" --mode readonly
```

单任务模式默认不得进入需要交互确认的操作；遇到未获授权的写入、执行、联网或危险行为时，返回明确的未完成状态和原因。

### 2.2 任务状态

```text
idle -> understanding -> awaiting_approval -> running -> verifying
                                      |                       |
                                      v                       v
                                  cancelled              completed / failed
```

- `understanding`：代理读取允许的上下文，必要时提出澄清问题或形成计划。
- `awaiting_approval`：需要用户决定的副作用操作不能执行。
- `running`：正在调用已授权工具、写入文件或执行命令。
- `verifying`：修改完成后执行已允许的验证，收集结果。
- `completed`：交付变更摘要、验证证据和已知限制。
- `failed`：保留失败工具输出，说明未完成内容，不伪造成功。

## 3. 权限与交互

### 3.1 授权模式

| 模式 | 自动允许 | 每次确认 | 禁止 |
| --- | --- | --- | --- |
| `readonly` | 工作区安全读取、搜索、Git 查询 | 无 | 写文件、执行命令、联网 |
| `confirm`（默认） | 安全读取、搜索、Git 查询 | 文件写入、命令执行、联网 | 危险操作 |
| `agent` | 安全读取、项目内文件写入、预批准的验证命令 | 其他命令、联网、危险操作 | 未批准的危险操作 |
| `auto` | 已配置策略内的读写和验证 | 策略外命令、联网、危险操作 | 明确禁用项 |

模式是执行策略，不是传给模型的一句提示。每次工具调用都由策略引擎根据工具类别、目标路径、命令风险和当前授权重新判定。

### 3.2 确认交互

需要确认时，CLI 显示操作类型、目标、理由、影响摘要和可选范围。用户可批准一次、批准相同类别直到本任务结束、拒绝或中断任务。

写文件确认必须显示统一 diff；命令确认必须显示工作目录、argv、网络状态、超时和沙箱策略。模型不得把确认文本解释为命令或权限配置。

### 3.3 不可绕过的安全边界

- 只能访问显式工作区内的路径，禁止路径穿越和符号链接逃逸。
- 默认拒绝读取 `.env`、私钥、凭据目录、Git 凭据和其他敏感文件。
- 命令执行必须使用结构化 argv；不能默认以 `shell=True` 执行模型生成的文本。
- 执行环境默认无网络，且不继承宿主密钥、代理、容器 socket 或用户目录。
- 超出策略的高风险操作，例如删除大量文件、修改 Git 历史、提升权限或访问工作区外文件，默认拒绝。

## 4. Agent 执行闭环

### 4.1 标准流程

```text
用户目标
  -> 解析当前模式与工作区
  -> 收集安全的项目上下文
  -> 模型提出下一步或调用工具
  -> 策略检查与必要确认
  -> 工具执行并规范化结果
  -> 工具结果回灌模型
  -> 继续直到完成、失败、取消或等待用户
  -> 验证、汇总与持久化任务记录
```

代理每轮最多执行有限次数的工具调用，并设置总时长、输出大小、上下文 Token 和失败次数上限。达到上限时，保留已完成结果并请求用户继续，而不是无限循环。

### 4.2 工具能力分期

首批内建工具：

| 类别 | 工具 | 约束 |
| --- | --- | --- |
| 项目理解 | 列目录、搜索文本、读取文件、Git 状态/diff | 只读、工作区与敏感文件策略 |
| 修改 | 创建、替换、补丁应用、撤销本任务修改 | 必须生成 diff，写入策略检查 |
| 验证 | 运行明确的测试、格式化、类型检查或构建命令 | 沙箱、超时、资源和输出限制 |
| 会话 | 查看状态、取消、查看本轮 diff、恢复待确认操作 | 仅影响当前会话/任务 |

后续工具：MCP Server、Git 提交、网络检索、Issue/PR 系统和 IDE 集成。它们都必须经过同一权限和审计模型，不能成为安全旁路。

### 4.3 上下文优先级

向模型提供上下文时按以下优先级裁剪：当前用户目标和安全规则、当前文件与工具事实、最近任务状态、相关项目文件、会话记忆、长期偏好。历史记忆不是高优先级指令，当前文件和工具输出可以覆盖旧记忆。

现有 `ChatService` 的模型适配、Token 预算、语言提示和记忆能力可以复用；新增的 Agent Runner 负责工具循环和任务状态，不应将工具执行逻辑堆入 API 或 CLI 展示层。

## 5. 首期范围与验收

### 5.1 首期必须交付

- `codemate` 交互式 TTY 会话和 `codemate run` 单任务入口。
- 工作区选择、明确显示的当前目录与会话 ID。
- 流式模型回答，以及统一显示模型文本、工具调用、确认请求和错误。
- 受工作区策略保护的列目录、搜索、读取文件、Git 查询工具。
- 小范围文件编辑、diff 预览、确认写入及本任务内撤销。
- 受限命令执行，至少支持项目测试、格式化和类型检查；无沙箱时拒绝执行，不能回退到宿主机直接运行。
- `readonly`、`confirm`、`agent` 三种真实生效的权限模式。
- 任务完成摘要：修改文件、执行命令、验证结果、失败项和遗留风险。

### 5.2 首期验收标准

- 在 `readonly` 下，任何写入或命令执行尝试均被拒绝且不改变工作区。
- 在默认模式下，编辑前能展示准确 diff，未经确认不会写入文件。
- 命令执行显示完整 argv 与工作目录，超时和非零退出码能被清晰返回。
- 任务中断后不再启动新工具；已发生的文件变更仍可查看和撤销。
- 文件访问不能逃出工作区，不能读取默认敏感路径。
- 模型或工具失败时，CLI 保留结构化失败原因，不将失败描述为已完成。
- 同一会话可以基于前一轮的文件修改和工具输出继续工作，且上下文受 Token 预算控制。

### 5.3 明确非目标

- 首期不提供任意 shell、任意网络、工作区外访问或无人值守的危险操作。
- 首期不自动提交 Git、不重写历史、不自动安装依赖。
- 首期不保证模型生成代码正确；验证结果是交付的一部分。
- 首期不将完整源码、密钥或完整终端历史默认持久化。
- 首期不要求 Web、VS Code、MCP 和远程团队协作同时完成。

## 6. 后续分期

| 阶段 | 目标 | 关键增量 |
| --- | --- | --- |
| P0：交互代理内核 | 让 CLI 在本地项目完成受控编码闭环 | Agent Runner、内建工具、授权、diff、沙箱验证 |
| P1：可靠性与项目理解 | 提升复杂仓库任务的成功率和可恢复性 | 相关文件检索、任务持久化、恢复、Git 工作流、测试建议 |
| P2：可扩展工具 | 扩展但不削弱安全边界 | MCP Client、工具白名单、远程服务授权、IDE 复用 |
| P3：协作与自动化 | 支持团队与受控非交互任务 | 项目规则、审计、CI 模式、PR/Issue 集成 |

## 7. 对现有项目的架构约束

- CLI、未来 Web 和 VS Code 客户端只负责交互，不直接实现模型循环或文件系统操作。
- `app/adapters/models/` 继续负责 provider 差异；Agent 层只依赖统一的模型和工具协议。
- 文件访问、补丁写入、命令执行、Git 与 MCP 都通过独立工具适配器；API、CLI 和模型都不得绕过安全策略直接操作宿主机。
- 会话记忆与任务状态分离：记忆保存对话背景，任务记录保存工具事实、审批、diff、命令和结果。
- Web 现有的 `operation_mode` 需在 Agent Runner 落地后复用真实权限策略；在此之前它不能被宣传为自动执行能力。

## 8. 成功度量

| 指标 | 含义 |
| --- | --- |
| 可验证任务完成率 | 有至少一次成功验证或用户明确接受的已完成任务比例 |
| 未确认副作用数 | 未经授权发生的写入、命令或联网次数，目标为 0 |
| 任务恢复率 | 中断后可查看状态、变更和继续/撤销的任务比例 |
| 验证覆盖率 | 有代码改动的任务中，执行过相关检查的比例 |
| 首次有效反馈时间 | 从提交任务到模型文本或首个可见工具状态的时间 |
| 用户撤销率 | 已应用编辑被撤销的比例，用于识别修改质量或授权体验问题 |

## 9. 术语

| 术语 | 定义 |
| --- | --- |
| Agent Runner | 管理模型与工具多轮循环、任务状态和停止条件的服务层。 |
| 工具调用 | 代理请求执行的结构化本地或远程能力，不等同于模型文本。 |
| 授权模式 | 对工具调用生效的策略集合，决定自动允许、确认或拒绝。 |
| 工作区 | 用户明确允许代理访问的项目根目录。 |
| 验证 | 对修改执行测试、格式化、类型检查、构建或其他可观察检查。 |
