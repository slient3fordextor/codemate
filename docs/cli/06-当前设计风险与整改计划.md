# 当前设计风险与整改计划

> 建立日期：2026-08-03。本文是 Agent CLI P0 的工程风险台账。风险只有在代码、测试和文档三者一致后才能标记为“已修复”；概念设计或接口占位不等于能力可用。
>
> 问题根因、修复经验和后续复盘模板统一记录在 [Agent CLI 问题复盘与工程方法论](07-AgentCLI问题复盘与工程方法论.md)，本文只维护风险状态和验收边界。

## 1. 风险处理原则

整改优先保证事实可靠，其次才增加图的表达能力：

1. 状态只能由运行时修改；
2. 完成结论必须引用系统可验证的证据；
3. 所有文件变更都必须进入交付清单；
4. 循环停止原因、预算和审批必须可以持久化；
5. 沙箱和多层规划在没有执行器验证前不得写成已实现能力。

## 3. P0 验收证据

以下场景必须有自动化测试：

- 修改公开返回的节点快照不会改变图内部状态；
- 已就绪或已运行节点不能再增加入边；
- 硬条件 `PASS` 无有效证据时不能完成；
- N/A 软偏好不影响质量分；
- 新建文本文件、二进制文件和空文件都出现在变更清单中；
- 普通 ReAct 动作不消耗或触发重规划审批；
- Loop 明确返回完成、等待审批和预算耗尽；
- 事件重放后节点状态、attempt、output 和边与原图一致；
- 没有实际执行后端时，沙箱执行前检查必须拒绝放行；
- Git 超时和仓库内 worktree 根目录以受控错误结束。
- Bubblewrap 内网络不可用，未批准 Python 入口被拒绝；
- SQLite 图、Loop 和任务状态可重放，重复 checkpoint 幂等；
- 交付成功包含空文件，原工作区同路径变化会阻止交付；
- 原生工具调用分块能汇聚为一次受校验的工具动作。

## 4. 暂不宣称已解决的边界

受控编码闭环已经落地，但以下扩展能力不属于当前 P0 承诺：

- `all_success`、`all_terminal`、quorum 等完整 Join Executor；
- TaskGraph、PhaseGraph、UnitLoop 的预算继承和局部重跑；
- Windows/macOS 原生沙箱后端；当前命令执行要求 Linux Bubblewrap；
- 跨机器共享任务数据库和限流；多机部署由网关与外部存储负责；
- 自动 Git commit、push、历史重写或无人值守交付。

这些边界不影响当前串行的“规划 -> 修改 -> 验证 -> 评估 -> 审批 -> 交付”链路；引入时仍需单独评测，不能绕开现有策略。
