# 技术选型

## 1. 总体架构

```text
客户端层
  Web 工作台
      |
API 层
  鉴权 / 限流 / 日志 / 路由
      |
核心服务层
  对话服务 / 上下文服务 / 代码修改服务 / 任务服务
      |
基础设施层
  SQLite 或 PostgreSQL / 可选 Redis / 本地文件索引 / 可选向量索引
      |
模型层
  本地模型 / 第三方模型 API / 可插拔模型适配器
```

## 2. 核心模块

| 模块 | 职责 | MVP 建议 |
| --- | --- | --- |
| 对话服务 | 管理会话、调用模型、流式返回 | FastAPI + SSE |
| 上下文服务 | 读取文件、检索片段、裁剪上下文 | 文件索引 + 简单检索 |
| 代码修改服务 | 生成修改建议和变更预览 | diff 生成与校验 |
| 任务服务 | 记录任务状态、耗时、错误 | 优先 SQLite，后续 PostgreSQL |
| 安全服务 | 限流、敏感信息检测、日志脱敏 | 规则和中间件 |

## 3. 后端框架对比

MVP 后端需要支持流式响应、异步模型调用、清晰 API 结构、本地部署和后续插件扩展。

更完整的后端候选方案分析见 [05-后端方案对比.md](05-后端方案对比.md)。

| 方案 | 优势 | 劣势 | 适配度 |
| --- | --- | --- | --- |
| FastAPI | 原生异步、类型提示友好、自动生成 OpenAPI、直接支持 SSE/WebSocket、适合 AI API 服务 | 后台管理能力弱于 Django，需要自行定义工程结构 | 高 |
| Django + Ninja | 生态成熟、ORM 和 Admin 强，适合复杂业务系统 | 框架较重，异步和流式体验不如 FastAPI 直接 | 中 |
| Flask | 轻量、简单、生态成熟 | 类型约束、异步、OpenAPI 和工程结构需要额外补齐 | 中低 |
| Node.js + NestJS | 模块化强、WebSocket 生态好、适合前后端同语言团队 | 与 Python AI、代码解析、本地模型工具链衔接成本更高 | 中 |
| Go + Gin | 性能好、部署简单、并发能力强 | AI SDK、代码分析和迭代效率不如 Python 方便 | 中 |

## 4. 推荐结论

MVP 推荐使用 FastAPI 作为后端骨架。

原因：

1. 与 Python AI 工具链、代码解析、向量检索、本地模型工作流集成成本最低。
2. 原生异步适合长时间第三方模型 API 调用和流式输出。
3. 自动生成 OpenAPI 文档，便于 Web、CLI 和后续插件接入。
4. 足够轻量，适合开源本地部署和用户二次开发。

## 5. FastAPI 骨架范围

确认采用 FastAPI 后，MVP 骨架建议包含：

| 模块 | 内容 |
| --- | --- |
| app/api | 对话、项目、模型配置、任务状态 HTTP API |
| app/core | 配置、日志、错误处理、依赖注入 |
| app/models | Session、Message、Task、Feedback 数据结构 |
| app/services | 对话编排、上下文检索、模型适配、代码修改 |
| app/adapters | 第三方模型 API、本地模型、文件系统适配器 |
| app/storage | SQLite/PostgreSQL 存储、项目索引、缓存 |
| tests | API、服务层、模型适配器测试 |

首版骨架包含：

1. FastAPI 应用入口和健康检查。
2. 模型配置 API，支持本地模型和第三方 API Key。
3. 对话 API，包含流式输出占位实现。
4. 项目文件读取 API，限制在用户配置的本地工作区路径内。
5. 基础任务状态 API。

## 6. 数据模型

```python
class Session:
    id: str
    user_id: str
    project_id: str
    created_at: str
    updated_at: str


class Message:
    id: str
    session_id: str
    role: str
    content: str
    context_files: list[str]
    created_at: str
    tokens_used: int


class Task:
    id: str
    user_id: str
    session_id: str
    type: str
    status: str
    error: str | None
    started_at: str
    completed_at: str | None


class Feedback:
    id: str
    message_id: str
    rating: int
    accepted: bool
    comment: str | None
```

## 7. 上下文策略

MVP 不实现复杂长期记忆，采用三层上下文：

| 层级 | 内容 | 生命周期 |
| --- | --- | --- |
| 当前上下文 | 当前文件、选中代码、用户输入 | 单次请求 |
| 会话上下文 | 最近 10 轮对话和关键摘要 | 当前会话 |
| 项目上下文 | 文件树、相关片段、索引摘要 | 项目周期 |

上下文优先级：

1. 用户输入。
2. 当前文件或选中代码。
3. 最近对话。
4. 检索到的相关片段。
5. 项目结构摘要。

## 8. 初始技术选择

| 领域 | MVP 选择 | 说明 |
| --- | --- | --- |
| 后端 | FastAPI | 推荐方案 |
| API 流式输出 | 优先 SSE | 后续可增加 WebSocket |
| 存储 | 优先 SQLite | 团队或远程模式再引入 PostgreSQL |
| 缓存 | 优先内存缓存 | 后续可选 Redis |
| 模型适配 | OpenAI 兼容 API + 本地模型适配器 | 后续增加 provider-specific 适配器 |
| 文件索引 | 本地文件系统索引 | 向量索引可选 |
| 测试 | pytest | 优先覆盖 API 和服务层 |
