# 里程碑、风险与评审问题

## 1. 里程碑

### Phase 1：MVP 验证，8 周

- Web 工作台基础界面。
- 对话式编程。
- 当前文件和项目文件树上下文。
- Python、JavaScript、TypeScript 代码生成。
- 基础日志、限流、错误处理。
- 如果确认框架选型，生成 FastAPI 后端骨架。

### Phase 2：产品化，8 周

- 代码修改预览和应用流程。
- 基础检索或向量索引。
- VSCode 插件 Alpha。
- 用户反馈闭环。
- 使用量和成本可视化。

### Phase 3：团队工作流，8-12 周

- 团队空间。
- 规则检查。
- PR 辅助。
- 执行沙箱 Beta。
- 多模型适配器。

### Phase 4：高级能力，持续推进

- 私有化部署包。
- 高级审计。
- 权限和合规增强。
- 长期记忆和个性化能力。

## 2. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 模型输出质量不稳定 | 用户信任下降 | 增加上下文约束、反馈闭环、重新生成 |
| 第三方 API 成本难控制 | 用户使用成本不可预测 | 成本提示、用量统计、用户自带 Key、本地模型选项 |
| 项目上下文不准确 | 生成代码不可用 | 优先当前文件，逐步增强检索 |
| 用户代码安全风险 | 代码泄露或合规问题 | 本地优先、日志脱敏、敏感信息检测 |
| 竞品压力 | 获客更难 | 聚焦轻量工作流和本地项目上下文 |

## 3. 待评审问题

1. MVP 是否只包含 Web 工作台，VSCode 插件是否移到 Phase 2？
2. 首批支持语言是否限定为 Python、JavaScript、TypeScript？
3. 项目上下文应该读取整个本地仓库，还是只读取用户选择的文件？
4. 代码执行沙箱是否进入 MVP？
5. 首批适配哪些本地模型和第三方模型 API？
6. 是否现在生成 FastAPI 骨架，还是先完成技术选型评审？
7. 开源许可证选择 MIT、Apache-2.0 还是 AGPL-3.0？

## 5. 术语表

| 术语 | 定义 |
| --- | --- |
| Token | 模型处理文本的基本单位 |
| 上下文窗口 | 模型单次请求可处理的最大文本范围 |
| RAG | 检索增强生成 |
| 沙箱 | 隔离执行代码的受限环境 |
| 首 Token 延迟 | 用户提交请求后收到第一段模型输出的时间 |
