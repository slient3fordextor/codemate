# 应用启动与请求入口

## 触发条件

使用 `make dev` 启动 Uvicorn，加载 `app.main:app`。模块导入时即执行 `create_app()`。

## 启动流程

```text
get_settings()
  -> 从环境变量和当前工作目录 .env 读取 Settings
  -> 配置日志
  -> 创建 FastAPI 应用
  -> 按配置创建 SQLite 或进程内会话记忆仓库并挂到 app.state
  -> 注册请求 ID 中间件、访问日志中间件、异常处理器
  -> 挂载 /api/v1 路由、/static 静态资源、/ 与 /health
```

| 入口 | 当前行为 |
| --- | --- |
| `GET /` | 返回 `app/static/index.html`。 |
| `GET /static/*` | 由 `StaticFiles` 提供 CSS 与 JavaScript。 |
| `GET /health` | 非版本化健康检查。 |
| `GET /api/v1/health` | 版本化健康检查。 |
| `GET /api/v1/version` | 返回应用名、版本和 `v1`。 |
| `POST /api/v1/chat/completions` | 创建 SSE 对话流。 |
| `GET/PUT /api/v1/model-config` | 查询或更新模型配置。 |

## 请求经过的基础设施

1. `RequestIdMiddleware` 读取请求头 `x-request-id`；缺失时生成 UUID，保存到 `request.state.request_id`。
2. 下游处理完成后，响应头写回同一个 `x-request-id`。
3. `access_log_middleware` 统计处理耗时；当 `ACCESS_LOG_ENABLED=true` 时记录方法、路径、状态码、请求 ID 和毫秒耗时。
4. 路由处理器执行；若抛出未捕获异常，则由全局异常处理器转为统一 JSON 错误。

中间件不负责鉴权、限流或敏感信息检测。相关配置字段存在，但当前没有接入请求处理。

## 配置来源与生命周期

`Settings` 使用 Pydantic Settings，来源优先级包含环境变量和当前工作目录中的 `.env`。`get_settings()` 有进程内缓存；模型配置保存成功后会显式调用 `get_settings.cache_clear()`，其余配置变更需要重启进程或由调用方清理缓存。

会话仓库默认为 SQLite，首次读写时懒初始化 `~/.codemate/memory.sqlite3`，进程重启后可恢复。只有显式配置 `SESSION_MEMORY_BACKEND=memory` 时才使用重启后丢失的进程内仓库。
