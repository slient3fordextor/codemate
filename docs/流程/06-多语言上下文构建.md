# 多语言上下文构建

## 触发条件

对话请求存在 `current_file` 或 `selected_text` 时，`ChatService` 调用 `LanguageContextService.build_context_message()`。路由会为每个请求按当前工作区和语言配置创建该服务。

`LANGUAGE_SUPPORT_ENABLED=false` 时，不执行语言识别，退化为只输出“当前文件”和“选中文本”的旧格式。

## 路径与语言识别

```text
current_file
  -> 相对路径以 WORKSPACE_ROOT 拼接；绝对路径直接使用
  -> resolve() 规范化
  -> 不在工作区内：文件路径置空
  -> 扩展名识别 + 向上寻找项目标记文件
  -> 扩展名优先，项目类型仅补充置信度/包管理器信息
```

支持的扩展名：Python（`.py`、`.pyi`）、JavaScript（`.js`、`.jsx`、`.mjs`、`.cjs`）、TypeScript（`.ts`、`.tsx`、`.mts`、`.cts`）。无法识别时语言为 `text`。

项目标记文件：

| 语言 | 标记文件 | 包管理器判断 |
| --- | --- | --- |
| Python | `pyproject.toml`、`requirements.txt`、`setup.py`、`setup.cfg`、`uv.lock` | 默认 `python`；`uv.lock` 标为 `uv`。 |
| JavaScript | `package.json`、`jsconfig.json`、锁文件 | 默认 npm；优先 pnpm，其次 yarn。 |
| TypeScript | `tsconfig.json` 与 JavaScript 标记文件 | 同 JavaScript。 |

## 上下文构建流程

1. 根据检测到的语言从注册表取得适配器。
2. 若没有适配器或找不到项目，只生成语言、合法文件路径与选中文本。
3. 找到项目后，适配器向上定位最近的项目根目录，记录现有配置文件、`src` 源码目录与 `tests`/`test` 测试目录。
4. 适配器生成项目摘要和建议提示，合成一条 system 消息。

最终 system 消息可包含：当前语言、当前文件、项目摘要、语言提示和选中文本。当前实现**不会读取当前文件正文、相关文件正文或目录树**，`related_files` 也不会渲染到消息里。

## 当前配置边界

`LANGUAGE_DEFAULT_LEVEL`、`LANGUAGE_CONTEXT_MAX_FILES`、`LANGUAGE_CONTEXT_MAX_BYTES`、`LANGUAGE_ENABLE_TREE_SITTER`、`LANGUAGE_ENABLE_LSP` 已能从环境读取并传入配置对象，但现有 L1 规则实现未使用这些值执行文件收集、字节裁剪、tree-sitter 或 LSP 调用。它们是后续增强预留项，不代表已具备对应能力。
