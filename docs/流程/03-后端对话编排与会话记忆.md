# 后端对话编排与会话记忆

> 文档定位：运行流程版，只描述当前代码已实现的行为。
> 设计原因和边界见
> [`docs/engineering/zh/11-L1会话记忆设计.md`](../engineering/zh/11-L1会话记忆设计.md)。

## 请求入口

`POST /api/v1/chat/completions` 必须提供 `message` 或 `messages`。路由按本次模型名创建 `TokenCounter`，再使用配置的 `MODEL_CONTEXT_WINDOW` 创建 `ContextBudgetPlanner`。

- 已知 OpenAI 兼容模型：使用 `tiktoken` 精确计数。
- 未知或非 OpenAI tokenizer：使用 `EstimatedTokenCounter`，并在事件中标记 `estimated=true`。
- `messages` 模式视为调用方提供完整历史，不叠加服务端记忆。
- `message` 模式在启用记忆时读取 L1/L2/L3。

## 读取与组装

```text
创建模型适配器、语言上下文服务和 Token 预算器
  -> 取得或生成 session_id
  -> 构造本轮必须保留的文件/选区、操作模式和当前 user 消息
  -> 计算剩余 memory Token 预算
  -> SQLite 显式读事务取得 L1、L2、L3 同一快照
  -> 解决当前指令/L1/L2/L3 冲突
  -> 按预算选择完整 L1 轮次、相关 L3、L2 摘要块
  -> 验证最终输入没有超过模型窗口
  -> 发送 context.usage
  -> 调用模型并转发流式事件
```

单条 `message` 模式的最终顺序为：

1. 当前文件/选区生成的 system 上下文；
2. 当前操作模式 system 消息；
3. 低信任 `memory_context`：L3、L2；
4. L1 历史 user/assistant 完整轮次；
5. 当前 user 消息。

L2/L3 不使用 system 角色。当前 user 明确要求覆盖同 key 的历史偏好；L1 新要求会过滤 L2 中已过期的相反指令；项目偏好在当前项目覆盖全局偏好。

## Token 预算行为

```text
input_budget = context_window - output_reserve - 5% protocol_margin
```

默认 `output_reserve=1024`。必需上下文本身超限时，在调用 provider 前发送 `CONTEXT_BUDGET_EXCEEDED`。记忆选择顺序是最近完整 L1、相关 L3、L2；任何一次选择都重新计算消息 Token。

`context.usage` 字段包括：

- `counter_id`、`estimated`；
- `input_tokens`、`memory_tokens`、`input_budget`；
- `output_reserve`、`protocol_margin`。

## 写入与智能压缩

模型正常结束后才提交记忆：

```text
user/assistant 敏感内容落盘前脱敏
  -> BEGIN IMMEDIATE
  -> 按 request_id INSERT OR IGNORE 本轮
  -> 超过 L1 轮数的旧轮转为 SummaryChunk
  -> 摘要块超 Token 上限时合并旧块并重新压缩
  -> 提取稳定 L3 偏好并裁决同 key 新旧值
  -> 淘汰超出 max_sessions 的最旧会话
  -> commit
```

压缩会抽取目标、约束、决策、待办和证据，并记录阶段、原因、压缩前后 Token、丢失项、版本和来源轮次。必保项验证失败会回滚整个写事务，因此不会先删原文再留下残缺摘要。

摘要再次超限时会继续合并最旧相邻块，而不是截断整份字符串。请求时如果 L2 仍装不下剩余上下文预算，则不注入最旧摘要；当前请求不受影响。

## 多进程与重启

默认 `SESSION_MEMORY_BACKEND=sqlite`，路径为 `~/.codemate/memory.sqlite3`。每次公开读写通过 `asyncio.to_thread()` 进入短 SQLite 连接，启用 WAL、外键、5000ms `busy_timeout`；写事务使用 `BEGIN IMMEDIATE`。多个本机 worker 和应用重启读取同一文件。

`backend=memory` 只有进程内 L1。`GET /api/v1/memory/capabilities` 会返回真实层级和持久化能力，不将其描述为 SQLite 的等价降级。

## SSE 事件

| 类型 | 说明 |
| --- | --- |
| `context.usage` | provider 调用前报告上下文计数与预算 |
| `message.start` | 首次带 `session_id` |
| `message.delta` | 增量 `content` |
| `usage.update` | provider 返回的输入/输出 Token |
| `message.done` | 完成原因 |
| `memory.warning` | 回答已完成，但记忆写入失败 |
| `error` | 上下文、记忆读取或 provider 失败 |

记忆读取发生在 provider 开流前。读取失败会产生 `MEMORY_STORE_ERROR`，不会静默继续。模型异常不保存半截回答；模型已完成后写记忆失败则保留回答并发送 `memory.warning`。

## 管理与遗忘流程

```text
GET    /api/v1/memory/capabilities
GET    /api/v1/memory/preferences
GET    /api/v1/memory/conflicts
DELETE /api/v1/memory/preferences/{preference_id}
DELETE /api/v1/memory/sessions/{session_id}
DELETE /api/v1/memory/project
DELETE /api/v1/memory/global-preferences
```

项目清理只删除当前 `project_root` 的会话、项目偏好和冲突记录。全局偏好必须调用独立端点。删除单条偏好会同时删除关联冲突审计，满足明确遗忘语义。

## 当前限制

- 当前不调用模型执行 C3 语义压缩；默认路径是确定性的 C1/C2/C4。
- 无结构化 key 的自由文本冲突不做伪精确裁决。
- 管理 API 尚无独立认证层，服务公开监听前必须由部署层保护。
- SQLite 只支持单机多进程，不支持多机共享。
