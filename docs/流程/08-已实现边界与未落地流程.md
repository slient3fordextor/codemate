# 已实现边界与未落地流程

本页用于区分“代码可运行”与“需求/设计已提出”。以下结论以当前仓库实现为准。

## 已完成的主流程

- 本地 Web 对话页面、会话 ID 恢复和 SSE 增量渲染；
- 模型配置查询与写回 `.env`；
- mock、OpenAI 兼容和 Anthropic 的流式模型适配；
- 单条消息模式的 SQLite L1/L2/L3 分层记忆；
- Token 整体预算、确定性记忆冲突检测、分块智能压缩和记忆管理 API；
- Python、JavaScript、TypeScript 的规则式语言和项目类型提示；
- 健康检查、请求 ID、访问日志和统一 HTTP 错误响应。
- `codemate`/`codemate run` Agent：`readonly/confirm/agent` 策略、受限读取/Git、diff 提案与审批写入、Bubblewrap 验证、worktree 隔离、SQLite checkpoint 及显式 deliver/discard；
- API 默认仅允许本机访问，可显式启用 Bearer Token 远程访问，并有进程内固定窗口限流；
- 模型网络适配器在尚未产生流式输出时，对超时、传输错误、429 和 5xx 进行有限重试；
- 模型配置以原子替换写入实际加载的项目根 `.env`，并拒绝覆盖由进程环境变量管理的配置。

## 尚未接入运行链路

| 主题 | 当前状态 |
| --- | --- |
| 文件树、文件读取、相关文件检索 | 只读 CLI 已有目录、文件和字面量搜索工具；尚无语义检索、相关文件排序、并行读取 Scheduler 或 Web 文件接口。 |
| 当前文件内容 | `current_file` 仅做路径/语言判断，不读取正文。 |
| 自动代码修改与变更预览 | 页面只渲染和复制模型答案；没有补丁解析、文件写入、审批或回滚流程。 |
| 命令执行与验证 | 页面可标记 Shell 代码并提供解释、复制；没有执行沙箱或服务端命令执行。 |
| 通用任务状态持久化 | `StorageConfig` 默认关闭，`app/storage/` 没有可用的通用任务持久化流程；记忆模块已独立使用 SQLite。 |
| 记忆管理与多机共享 | 已有偏好/冲突查询和删除 API，尚无管理 UI、编辑/恢复、数据库加密；SQLite 只支持单机多进程。 |
| 重试 | OpenAI 兼容与 Anthropic 适配器只在首个流式块前有限重试；命令不自动重试，未知中断结果恢复后要求审批。 |
| 限流和敏感内容检测 | API 支持进程内固定窗口或共享 SQLite 限流；多机统一边界由网关负责。敏感检测已用于记忆落盘和工具路径/内容过滤。 |
| tree-sitter、LSP、按字节/文件数裁剪 | 多语言配置项存在，L1 实现未调用这些能力。 |
| SSE 取消 | 前端有 `AbortController`，界面没有取消入口；服务端没有取消任务管理。 |
| 写入、验证与隔离 | 可写任务使用独立 Git worktree、审批补丁和无网络 Bubblewrap 验证；源工作区仅在显式 `deliver` 且无重叠冲突时更新。 |
| Agent 恢复 | 执行图和 Runner 当前只在内存中；没有 SQLite TaskRun/事件事务、崩溃恢复或跨进程锁。 |
| 工具协议 | Runner 使用严格 JSON 决策协议并校验参数；尚未适配 OpenAI/Anthropic 原生 tool-call 事件。 |

## 维护原则

新增能力时应先更新对应流程文档：说明入口、前置条件、成功路径、失败与取消分支、持久化边界，以及是否会向模型发送文件内容。这样流程文档可以继续作为代码审查和联调的依据。
