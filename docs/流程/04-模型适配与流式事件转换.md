# 模型适配与流式事件转换

## Provider 选择

`build_model_adapter()` 按 `MODEL_PROVIDER` 选择实现：

| provider | 适配器 | 请求协议 |
| --- | --- | --- |
| `mock` | `MockModelAdapter` | 不发网络请求，生成固定模拟响应。 |
| `anthropic`、`claude` | `AnthropicClaudeModelAdapter` | Anthropic Messages API。 |
| `openai_compatible`、`ollama`、`deepseek`、`qwen`、`zhipu`、`moonshot`、`baichuan` | `OpenAICompatibleModelAdapter` | OpenAI Chat Completions SSE 兼容协议。 |

OpenAI 兼容类 provider 必须配置 `MODEL_BASE_URL`；Anthropic 可省略地址，默认使用 `https://api.anthropic.com/v1`。当前 `MODEL_MAX_RETRIES` 只被保存和返回，适配器没有重试循环。

## OpenAI 兼容流程

```text
将全部 ChatMessage 原样序列化为 messages
  -> POST {base_url}/chat/completions
  -> Authorization: Bearer <api_key>（有密钥时）
  -> 解析上游 data: 行
  -> 映射为 message.start / message.delta / usage.update / message.done
```

- 请求体固定 `stream: true`，并按需加入 `temperature` 和 `max_tokens`。
- 上游 HTTP 状态码大于等于 400 时读取最多 200 字节响应体，抛出 `MODEL_PROVIDER_ERROR`。
- 超时转换为 `MODEL_PROVIDER_TIMEOUT`，其他 HTTP 错误转换为 `MODEL_PROVIDER_ERROR`。
- `[DONE]` 和空数据都会映射为 `message.done(stop)`；无法解析的行会跳过。

## Anthropic 流程

```text
拆分 system 消息到顶层 system 字段
  -> 非 system 消息保留 user / assistant 角色
  -> POST {base_url}/messages
  -> 解析 Anthropic SSE type
  -> 映射为统一 ModelChunk
```

使用 `x-api-key` 与 `anthropic-version: 2023-06-01` 请求头。未提供 `max_tokens` 时向 Anthropic 发送默认值 `1024`。`tool` 角色在此适配器中会被归并为 `user`。

| 上游 type | 标准事件 |
| --- | --- |
| `message_start` | `message.start`，可带输入 token。 |
| `content_block_delta` | `message.delta`。 |
| `message_delta` | `usage.update`，可带输出 token 和停止原因。 |
| `message_stop` | `message.done(stop)`。 |
| `error` | 抛出 `ModelProviderError`，由对话层转成 SSE `error`。 |

## Mock 流程

Mock 适配器从最后一条 user 消息取文本，按空格逐词输出 `Mock response: <文本>`，随后输出用量和 `message.done`。它用于本地联调，不模拟网络失败、取消或重试。
