# 模型配置读写

## 查询流程

```text
页面打开模型面板 / 添加模型
  -> GET /api/v1/model-config
  -> get_settings().model
  -> 返回 provider、地址、模型名、备注、超时、重试次数、上下文窗口和 api_key_set
  -> 页面不回填 API Key 明文，只展示是否已保存
```

`api_key_set` 是布尔状态，不会在响应中暴露 `MODEL_API_KEY`。

## 保存流程

```text
页面收集表单
  -> 计算 api_key_mode：clear / replace / preserve
  -> PUT /api/v1/model-config
  -> 根据模式选择新密钥、旧密钥或空值
  -> 更新工作区根目录 .env 的 MODEL_* 键
  -> get_settings.cache_clear()
  -> 再读取 Settings 并返回脱敏配置
```

受管理的键是：`MODEL_PROVIDER`、`MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY`、`MODEL_NOTE`、`MODEL_TIMEOUT_SECONDS`、`MODEL_MAX_RETRIES` 与 `MODEL_CONTEXT_WINDOW`。

- `replace`：使用请求中的 `api_key`，空值会写为空；
- `clear`：无条件清空密钥；
- `preserve`：保留当前 Settings 中的密钥。

写入时保留 `.env` 中不属于上述集合的行；已有受管理键原位置替换，缺失键追加到文件末尾。值为空时写成空赋值，包含空格、引号或 `#` 时使用双引号并转义反斜杠和双引号。

## 校验与影响范围

请求模型名不能为空，超时和上下文窗口必须大于零，重试次数不得为负。对于 OpenAI 兼容类 provider，缺少 `base_url` 会在重新读取配置时触发校验错误。`MODEL_CONTEXT_WINDOW` 会直接参与下一次对话的输入 Token 预算计算，必须填写所选模型真实支持的窗口。

保存后的配置用于**下一次**对话路由创建 `ChatService` 时选取适配器；已在传输中的流不会改变。`.env` 位于 `WORKSPACE_ROOT`，默认是服务进程启动时的当前工作目录。
